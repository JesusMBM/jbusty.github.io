The hidden cost of AI agents

An automated helper may consult its model many times before finishing a job. See what the meter counts, try a transparent example and compare selected published rates.

01 / AI costs

The model is one part of the job

The model proposes an answer or next action. Surrounding software supplies instructions, connects tools, tracks progress and decides whether to call the model again. Developers often call that software the harness. Like a cook working in a kitchen, a capable model needs a workflow around it; the workflow affects both results and cost.

02 / AI costs

What the meter counts

A token is a small piece of text used in processing and billing. It can be part of a word, a whole word or punctuation. Input includes instructions, documents, questions and earlier conversation. Output is generated material. Some systems also charge for reasoning that does not appear in the visible answer.

Sources: DeepSeek pricing · Grok caching and billing

The price cards use one million tokens as their unit. The calculator controls use thousands. Input and output have separate rates, so two requests with the same combined text size can cost different amounts. Subscriptions, tool calls, taxes and infrastructure can add charges outside a text-token calculation.

Try a simple job

This invented scenario sends the same reference text at every step and keeps earlier replies unchanged. No new tool results or user messages are added. Move one control at a time to see whether repeated reading, longer answers or more steps is driving the change. It is a worked example rather than a prediction of typical agent usage.

Estimate the text-model bill

Choose a rate card, step count, reference size and reply length. The receipt separates fresh input from reused input.

Sources: OpenAI API pricing · Anthropic pricing · Grok API pricing · DeepSeek pricing

With eight steps, 24,000 reference tokens and 2,000 reply tokens per step, total input is 248,000 tokens and output is 16,000. The reuse scenario contains 38,000 fresh input tokens and 210,000 reused tokens. Using Grok 4.6’s listed short-context rates gives $0.592 without caching and $0.277 with eligible reuse. These are arithmetic results from the stated assumptions.

Sources: Grok API pricing

For N steps, C reference tokens and O reply tokens per step, total input is N × C + O × N × (N − 1) / 2. Total output is N × O. Every later step rereads the fixed reference plus all earlier replies. The first request has no reused input; each following request treats the latest reply as fresh.

04 / AI costs

Saved input has its own rules

Prompt caching lets a provider reuse earlier processing for matching input. There may be a charge to write that material before later discounted reads. Entries can expire, and changed text near the beginning can prevent reuse. The calculator assumes the preceding input stays eligible; it does not promise that a real service will deliver those cache hits.

Sources: OpenAI prompt caching · Anthropic prompt caching

The selected OpenAI rows use writes at 1.25 times ordinary input and reads at one tenth. Claude uses five-minute writes at 1.25 times input; Fable 5.1 has a different read discount from Opus 5 and Sonnet 5. Grok and DeepSeek charge ordinary input for misses on these rate cards, with no separately listed write premium.

Sources: OpenAI API pricing · Anthropic pricing · Grok API pricing · DeepSeek pricing

Cached input still occupies the context window: the maximum material the model can handle at once. The calculator suppresses totals if a step exceeds its selected limit. It also checks each whole prompt for higher rates: above 272,000 input tokens for these OpenAI models, and at or above 200,000 for Grok 4.6.

06 / AI costs

Spend on useful progress

A low token price only helps if the job finishes acceptably. Try representative tasks, check the results and count repeated attempts. A cheaper model that needs more retries may cost more per successful outcome. A more expensive model is not automatically worth its price either.

  • Define what a finished, acceptable result looks like.
  • Provide relevant reference material and concise tool results.
  • Set a spending or stopping limit for repeated attempts.
  • Reuse stable instructions when the service supports it.
  • Compare total cost for work that passes the same checks.

Long jobs may use compaction, which summarizes earlier material, or a fresh session with a written handoff. Both can reduce carried context, but can lose details and require extra work. Anthropic’s harness experiments discuss both approaches; they do not establish that resets are always necessary or always cheaper.

Sources: Anthropic: long-running harness design

Words explained

Harness
Software coordinating the model, tools and task progress.
Context window
The amount of material a model can handle in one request.
Cache write
Storing eligible input for later reuse.
Cache read
Using eligible input saved from earlier processing.
Compaction
Replacing earlier context with a shorter representation.
Rate card
Published prices and conditions for a service.
