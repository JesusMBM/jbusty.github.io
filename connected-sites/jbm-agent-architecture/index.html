How an AI agent gets a job done

Follow how an AI system chooses a step, uses a tool, and checks the result. Learn what information it needs and where people should set limits.

By Jesus Bustillos-Molina · Reviewed 4 September 2026 · About 5 minutes

  • Make branches, permissions, and stopping rules explicit.
  • Add complexity only when it improves measured results.

01 / AI systems

What makes software an agent?

A model generates a response from the information it receives. A workflow arranges steps in a process. An agent lets a model choose some next steps while surrounding software carries them out. A chat window can contain any of these; its appearance does not reveal the architecture.

Sources: OpenAI · Anthropic

An agent can propose a tool call, inspect the result, and continue toward a goal. Words such as “choose” and “remember” describe software behavior here; they do not establish feelings or consciousness.

02 / AI systems

Follow one familiar job

Imagine planning a day at Kennedy Space Center with a $500 budget and an interest in space history. This is a teaching example, not a priced travel offer. The assistant needs the visit date, starting point, party size, and what the budget covers.

03 / AI systems

Six parts that work together

Building blocks and their jobs
PartWhat it does in the example
ModelInterprets the goal and proposes what to do next. Suggests a schedule after reading the available activities.
ToolsFunctions that can retrieve information, calculate, or make an allowed change. Look up official hours or add the budget with a calculator.
InstructionsExplain the task, constraints, boundaries, and what a finished result should include. Use the correct visit date and do not purchase tickets without a decision from the user.
StateRecords progress and facts for this run. Hours verified; travel time still missing; purchase not approved.
MemoryStores information for later use when the application is designed to retain it. A travel preference the user wants remembered for future plans.
EvaluationChecks whether the system meets its requirements on representative tasks. Can it notice a missing ticket fee or conflicting dates?

Sources: OpenAI · LangChain

These parts need not be separate services. A simple task may need no long-term memory. The model proposes actions; the application decides which operations may execute.

04 / AI systems

Choose, act, inspect—and know when to stop

Sources: OpenAI · Anthropic

The harness is the software managing this loop: it supplies context, tracks progress, controls tools, records outcomes, and handles recovery. Permission belongs in enforced checks, not merely in the model’s statement that an action is allowed.

Sources: OWASP Gen AI Security Project · OWASP API Security Project

05 / AI systems

Keep the working record useful

Context is the material available for the model’s current work: instructions, the request, source excerpts, tool descriptions, and relevant history. Keep the visit date, budget assumptions, confirmed facts, and unresolved questions. Retrieve detailed pages when needed and remove duplicate material. A summary can lose a crucial condition, so preserve its source. There is no universal percentage split for context.

Sources: Anthropic

State records this job’s progress. Saved checkpoints preserve state between steps; longer-term storage can retain information across conversations. An in-memory checkpoint will not survive a process restart. Retention and access rules matter whenever the application stores user information.

Sources: LangChain

Five useful ways to arrange the work

Patterns can be combined; each needs a failure route
PatternTravel exampleFailure or exit to define
Prompt chainingDraft, check, then revise the itinerary.Repair a failed check or stop; early mistakes can spread.
RoutingSend weather and ticket questions to different sources.Include an uncertain route when the category is unclear.
Parallel workCheck hours, weather, and travel together after agreeing the date.Combine only compatible evidence; handle missing results.
Coordinator and workersCreate an extra viewing-restrictions task if a possible launch matters.Limit new tasks, handoffs, and duplicate work.

Sources: Anthropic

Parallel work fits independent questions. If one answer determines the next question, keep those steps sequential. A second model can repeat the first model’s mistake, so objective checks still need sources or calculations.

07 / AI systems

Make the branches explicit

A graph is a map of work: nodes are steps, edges are permitted routes, and state records the current situation. A step may use code, a tool, or a model. LangGraph is one framework for implementing these stateful processes; using it does not guarantee a correct answer.

Sources: LangChain · LangChain

Example transitions after checking a draft
Check resultNext route
Missing evidenceReturn to source gathering.
Repairable schedule errorRevise the draft, then check again.
All requirements passDeliver the itinerary.
Missing user decisionPause and ask about the specific choice.
Blocked or attempt limit reachedStop and explain the remaining gap.

Sources: LangChain

Saved progress supports interruption and recovery, but a checkpoint does not undo an external action. Restarted code may run again. A booking operation needs duplicate prevention so that recovery cannot accidentally create two reservations.

08 / AI systems

Choose the smallest design that earns its cost

Use ordinary software for exact rules and structured inputs; use one model call when language interpretation or drafting is the main challenge. Add a fixed workflow for known stages, an agent loop for discovery-dependent actions, and persistent state when interruption or branching requires it. These are options, not a ladder every project must climb.

Sources: OpenAI · Anthropic

Start with one agent when it works reliably. Several agents can help with independent work or distinct tool access, but require a common brief, clear responsibility, and a way to reconcile results. Measure full-task success, waiting time, cost, and handoff errors. Another agent’s output remains evidence to inspect, not permission to act.

Sources: OpenAI · Anthropic

Test missing information, unavailable tools, ambiguous requests, and attempted misuse. Use code for arithmetic and hard limits, dated sources for changing facts, and clear stop conditions. Before deployment, assign an owner, restrict account access, protect stored records, and prepare to revoke access. Recheck representative tasks after models, tools, or rules change.

Sources: OWASP Gen AI Security Project · ASD ACSC, CISA, NSA, Canadian Centre for Cyber Security, NCSC-NZ and NCSC-UK

Words explained

Language model / LLM
Software trained on data to generate language and other supported outputs, including proposed tool calls.
Agent
Software that uses a model to select actions toward a goal and inspect the results.
Workflow
An arranged process of steps, branches, and checks.
API
A defined way for programs to request information or an action from another service.
Tool
A function an agent can call, such as search, calculate, or create a record.
Prompt
Instructions and information sent to a model.
Context
The information supplied for the model's current work.
Context window
The model's limit on active information and generated content; exact limits depend on the model.
Token
A small unit used to represent text or other supported input and output.
Retrieval
Finding stored information and bringing relevant parts into the current context.
State
The current working facts and progress of a run.
Memory
Information the application saves for use later.
Harness
The surrounding software that runs, controls, and records an agent's work.
Node / edge
A step in a workflow map / a route to the next step.
Checkpoint
A saved snapshot that supports continuation or recovery.
Evaluation
A repeatable check of how well the system meets its requirements.
Authorization
A check that a particular user or agent may perform a particular action.
Prompt injection
Instructions hidden in input or retrieved material that try to redirect the agent.
Idempotent action
An action designed so repeating the same request does not unintentionally repeat its effect.
